# 0004. Contribution and landing

Accepted. Every push permanently publishes code and runs its workflows; organisation admin bypass once admitted unchecked main, and REUSE lint alone accepts incorrect expressions.

## Decision

1. **Candidates.** Rebase `land/owner/<slug>` onto main and fast-forward only after green `ci / required`; at most three in flight. Fix/reland red candidates, never rerun them.
2. **Main.** Add a no-bypass repository ruleset requiring checks, linear history and no force-push/deletion: [rulesets compose by strictest rule](https://github.com/github/docs/blob/bcb11fe40765ec7935bdcff0da8cd3cee0bfba50/content/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/about-rulesets.md#L19-L64); only rebase merge remains enabled but unused, and Update branch is on.
3. **Authority.** [Runs receive only referenced secrets](https://github.com/github/docs/blob/bcb11fe40765ec7935bdcff0da8cd3cee0bfba50/content/actions/concepts/security/secrets.md#L20); only release publish-crates references `CRATES_IO_PUBLISH_NEW_TOKEN` for first final. Before that run/first release, narrow organisation Actions/Dependabot secrets from all repositories to selected private ones; owner decides App access, and no App/agent acts on issue/PR events.
4. **CI.** Run on pull_request and pushes to `land/owner/**`, never pull_request_target; cancel superseded runs per ref. Final required always runs and accepts only successful needs because [skipped jobs report success](https://github.com/github/docs/blob/bcb11fe40765ec7935bdcff0da8cd3cee0bfba50/data/reusables/actions/workflows/skipped-job-status-checks-passing.md).
5. **Contributions.** Read fork gate-surface diffs before approving runs; keep accepted PRs current with Update/rebase, then land their [exact sha](https://github.com/github/docs/blob/bcb11fe40765ec7935bdcff0da8cd3cee0bfba50/content/pull-requests/reference/pull-request-merges.md#L65-L69) as `land/owner/pr-<n>` to mark merged. Without maintainer-edit permission, rebase preserving author/trailers and close with a link; rewrite fork `.github/` changes and Dependabot updates as maintainer-signed candidates.
6. **Review/autonomy.** [CLAUDE.md](../../CLAUDE.md) owns premise validation, authorized work and approval boundaries; independently review every maintainer change before push. Gate-surface review compares named refusals before/after changes to `.github/`, `.cargo/`, Makefile, TOML/locks, build.rs, fuzz, `.git*`, licensing and every script a gate invokes.
7. **Commits.** DCO requires the tree to track `.github/signoff`, declaring every commit signed off, and author sign-off, subject ≤72 columns on its own line followed by blank/end, and no claude/anthropic/llm token as author/committer, except Dependabot on PRs; maintainer commit-msg hook refuses rather than adds missing sign-offs. [CONTRIBUTING](../../CONTRIBUTING.md) owns the one-way grant and DCO terms.
8. **Checks.** Run relevant checks during work and `make ci` on the final stable tree, honestly marking unavailable targets; rerun after relevant edits, failures or new evidence only. Gates must reject named failures; removing/replacing obsolete gates requires evidence and an owning-decision update, never merely green output.
9. **Privacy.** Policy hygiene rejects home paths, private addresses, personal email except published licensor/third-party notices, tracked ignored files and private branch names; pre-push also scans secrets. Only Signed-off-by, Co-authored-by, Fixes and Tier trailers are public; [leaks reachable from main remain public](https://github.com/github/docs/blob/bcb11fe40765ec7935bdcff0da8cd3cee0bfba50/content/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository.md#L149-L158): fix forward, delete logs and rotate credentials.
10. **Agent setup.** CLAUDE.md is the canonical instruction entry point; shared rules/procedures/reviews live once in `.claude/`, explicitly read without native discovery, and `make setup` validates tracked setup. Agents may implement, independent reviewers remain read-only and inherit the active model with another family consulted when available; machine facts/settings/memory/worktrees/tool state remain ignored.
11. **Attribution.** Rewrite unsigned outside snippets/patches test-first under DCO (b), sign off and credit their author with Co-authored-by. Root REUSE annotations override and retain MIT-bearing paths/copyright lines while files exist; DCO compares merge-base/tree, rejecting lost MIT-bearing membership/lines, missing override and newly MIT-only membership, or checks tree alone without a merge base.
12. **Security.** Prepare fixes privately, land under neutral slugs at disclosure, tag after rehearsal, then publish advisory.
13. **Release.** On-demand SemVer 0.x tags name landed main shas; read `.github/` diff since prior tag before pushing with maintainer credentials. ADR 0003 owns remaining release policy; environments permit self-review.

## Limits and rejected routes

- Every main sha after root heads a green candidate; enforce no-bypass rules, push protection and hooks before candidates. Stolen landing credentials can still publish self-judging code; independent review, pre-tag reading, tag rules/approval precede registry publication, and other landed code ships next tag.
- Push protection detects known secrets; pre-push alone blocks private patterns before publication. No human reviews maintainer pushes, so missed gate weakening publishes immediately and requires forward repair; noneditable fork/Dependabot PRs show Closed rather than Merged.
- Button merges admit unjudged shas, queues add another main path and non-cancelling CI delays current verdicts. Dependabot sign-off exceptions fail after rebases, and [adding commits stops Dependabot rebasing](https://github.com/github/docs/blob/bcb11fe40765ec7935bdcff0da8cd3cee0bfba50/content/code-security/how-tos/secure-your-supply-chain/manage-your-dependency-security/manage-dependabot-prs.md#L37).
- Signatures do not prove authorship: [GitHub signs web commits for any user](https://github.com/github/docs/blob/bcb11fe40765ec7935bdcff0da8cd3cee0bfba50/content/authentication/managing-commit-signature-verification/about-commit-signature-verification.md#L91). A second MIT path list would drift; scripts probing settings or enforcing make-only jobs have no demonstrated requirement.
