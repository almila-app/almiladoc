# 0002. OCR gaps and engine port

Accepted. The consumer parses without network in a child process, then OCRs in its parent through an OpenAI-compatible vision server returning Markdown; gaps avoid failing an otherwise readable PDF or returning truncated success.

## Decision

1. **Port.** Per-call synchronous `OcrEngine: Send + Sync` maps each `OcrRequest` (gap id, origin, reasons, PNG/JPEG image) to `Fill(GapFill)`, `Failed` or `Unattempted`, failures carrying only a closed `OcrFailureKind`, HTTP status and `Retry-After` (seconds or a date, read without a clock). `Parsed::ocr(engine, gaps)` exports `batch_size()` batches, applies fills/failures and stops after a batch with an unattempted gap.
2. **Two phases.** Between parse/render, `fill_gap` supplies content and `fail_gap` records `ocr_failed`; `ocr_requests(&RasterSpec, gaps)` exports pickleable requests. `ocr_pages: PageSelection` forces selected PDF pages to gaps (`caller_requested`), discarding their text without loss.
3. **Routing.** Page verdicts, explicit page selection and `ImageOcr` create gaps; each OCR call uses one engine/subset, and later calls receive only unsettled gaps.
4. **Images.** Opt-in `ImageOcr::All` adds embedded PNG/JPEG gaps after their innermost block, carrying asset bytes undecoded; other images report `image_not_ocred`. Filled text follows the block (`<br>` in cells); unsettled image gaps write nothing and never cause page-only `NeedsOcr`.
5. **Painting.** Reuse the retained unpdf parser, without system fonts, for crop-box sRGB PNGs at the largest dpi within the media-box pixel cap, on the call pool. Charge one unit/128 pixels and /16 PNG bytes; `render_page_with` charges each operation before it runs against a ledger shared by concurrent pages, rounding covered-pixel work up per 128, and stops on resource limit/cancellation.
   - Unpainted runs/images/inline images/undecodable streams report `raster_incomplete`; shadings and soft masks do not. A painted page's request carries its size and a per-kind `RasterFidelity` (unpdf's counts plus substituted runs), whose `lost()` is what `raster_incomplete` counts.
   - A gap whose image cannot be made is an `OcrRefusal` (`Unpaintable`, `OverBytes`) in `ocr_requests`' list and `OcrSummary.refused`, never a silent drop; it stays unfilled and drops any earlier request's unpainted count.
6. **Raster spec.** Default 150 dpi, 12,845,056 pixels (MiMo-VL cap), no byte bound; engine/caller supplied, outside `Config` because it shapes requests rather than fills. `max_bytes` refuses any encoded image over it, an embedded one before it is copied and a page's PNG after its painting and bytes are charged; it never repaints smaller.
7. **HTTP.** Feature `ocr-http` posts one image to `chat/completions` in a configured message layout, token field, temperature, image detail and service tier, at configured concurrency on the calling thread and scoped threads of its own, stripping a leading `<think>` block. Retry 408/429/500/502–504 with cancellable backoff; each 429 matching the configured tier fallback moves to the next tier until the last. Only 413, an oversized, refused or unfinished reply fails; 400/422, no text, an unreadable reply or a wrong `answer_model` leave the gap unattempted and stop taking requests in that batch.
   - `recognize_images` also reports token usage, the realized tier and each attempt's tier and status. Each call uses a fresh agent that a scoped watcher shuts down on cancel, closing requests in flight; a connect in progress runs to its 10 s timeout and a name lookup unbounded, and a cancelled body is never trusted.
   - ureq/rustls uses ring unless another process provider is installed, asks before sending bodies, refuses redirects, caps replies, uses only explicit proxies and leaves no workers behind. Caller PEM replaces Mozilla roots for endpoint/HTTPS proxy; keys require an HTTPS endpoint or direct loopback, and construction opens no socket.
8. **Local OCR.** Separately locked `ocr-local/` wraps Oar core on private CPU workers/sessions outside core/Python graphs; verified ONNX Runtime API 27 initialization must precede any other ORT use and cannot retry native failure.
9. **Files/bounds.** Local OCR verifies caller model/dictionary/runtime SHA-256s and downloads nothing; native work has no hard cancellation, memory or total-thread cap, so stronger bounds require caller-owned processes.
10. **Identity.** ADR 0001 decision 15 includes fills; engines stay outside `config_fingerprint`.
11. **Untrusted fills.** Non-exhaustive `GapFill` supports `Markdown`, `Lines(Vec<OcrLine>)` and `MarkdownTables`; every fill is NFC and atomic, limited by `max_ocr_text_bytes` (default 1 MiB), nesting and charged events. Lines have normalized horizontal boxes, are ordered/grouped by the core, stay literal and cost 32 additional bytes/box; Markdown escapes HTML and keeps only link labels/image alt text, and reads TeX math (`\(..\)`, `\[..\]`, `$..$`, `$$..$$`, `math` fences) as `Inline::Math`/`Block::Math` through one pre-scan that charges the bytes it scans and rewrites, while text without math costs the events it cost before; an unpaired delimiter stays text, and a rewrite the parser reads back differently falls back to the text as written.
    - OTSL runs (`<fcel>A<lcel><nl>`) starting in a top-level paragraph or HTML block outside code, comments, quotes and lists read as tables in every Markdown fill before the parser, through one tag scan of the fill that skips code, escapes, HTML tags, autolinks and math (`$..$` only when it neither starts nor ends at a cell tag and no digit follows its closing `$`, since such dollars are currency), so tags after an unclosed `<!--`, `<?`, `<![CDATA[` or doctype stay text: a run continues past blank lines while a cell tag follows each `<nl>`, a cell's text ends at the next tag, a blank line or the end of its paragraph or HTML block, spans come from the `<lcel>`/`<ucel>`/`<xcel>` rectangle, a stray continuation is an empty cell, a continuation or `<ecel>` with text a cell, short rows are padded, leading all-`<ched>` rows are the header and cell text is inline Markdown keeping hard breaks; repairs lose no text and never fail, while bytes, tags, span probes and grid positions are charged (`<otsl>` wrappers and `<loc_N>` are out of scope).
    - Tables opt into standalone text-only `table`/`tr`/`td` HTML with positive spans and OTSL tables, as safe merged cells at a top-level gap and with each merge shown once in a nested one; unsupported markup or a table inside a quote or list fails `InvalidTable`. Per-fill limits return `GapError::Refused { limit }`, unlike fatal work exhaustion.
12. **Containment.** Engines see only requests plus fill limits; panics become `Internal`, Python accepts only built-in engines and exports requests for custom OCR. Errors, diagnostics and Debug exclude OCR text, response bodies, server error messages, painter error text, keys, prompts and URL userinfo/query, and OCR results and refusals carry only fills, counts, tier indexes and closed kinds; ureq trace leaks keys, so Python compiles `log` out; sockets exist only in `src/ocr/http/`.
13. **Tests.** Fake engines and loopback HTTP suffice; the owner accepts the consumer's existing Xiaomi endpoint/settings without another live run before the first release.

## Limits and rejected routes

- Raster/HTTP add 1.02/0.88 MB to the wheel; ring requires clang on `windows-11-arm`. Annotation appearances, Lab/DeviceN colours and missing stand-in glyphs are not observed: they paint incorrectly without a diagnostic and `RasterFidelity` does not count them.
- hayro adds 2.82 MB and a second parser while hiding unpainted text; PDFium/MuPDF require native dependencies; reqwest requires tokio; tract-onnx adds 20.6 MB and runs 1.8× slower.
- Vision engines return Markdown, so located-line grouping belongs in the core rather than an engine. Putting an engine in Config loses Eq; a registry adds global state; white gap images invite invented text.
